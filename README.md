# PesaPap Growth Analytics: SQL, KPIs and an Onboarding Experiment

## Project summary
PesaPap is a Kenyan digital-payments start-up. This project gives the Head of Growth (1) a KPI scorecard, (2) SQL answers to eight business questions plus a data-validation check, (3) RFM segments and cohort retention, and (4) an analysis of an onboarding A/B test (group B saw a simplified sign-up screen), ending in a roll-out recommendation. Data is synthetic, generated by `generate_data.py` (seed 77): 3,000 users, 12,000 transactions (15 Jan to 13 Jun 2026) and 3,000 experiment assignments.

## Headline recommendation
**Roll out the simplified sign-up screen.** It converted 13.8% vs 10.5% (+3.3 pp, +32% relative, chi-square p = 0.005, 95% CI +1.0 to +5.7 pp). At about 760 sign-ups a month that is roughly 25 extra converted users a month, about KES 1.2M of extra annual transaction value. Keep a small holdout to confirm the effect. Target the **At Risk** RFM segment first for win-back. See `reports/growth_memo.md`.

## Database tables (SQLite `pesapap.db`)
| Table | Columns | Primary key | Foreign key |
|---|---|---|---|
| `users` | user_id, signup_date, county, acquisition_channel | `user_id` | none |
| `transactions` | txn_id, user_id, txn_date, product, amount | `txn_id` | `user_id` references `users(user_id)` |
| `experiment` | user_id, group, converted | `user_id` | `user_id` references `users(user_id)` (one-to-one with users) |

Relationships: one user has many transactions; one user has exactly one experiment row.

## Repository contents
| Path | Purpose |
|---|---|
| `generate_data.py` | Dataset generator (unchanged, seed 77); writes the three CSVs |
| `sql/queries.sql` | Validation query and questions a to h, each preceded by its business question |
| `pesapap_analysis.ipynb` | Builds `pesapap.db`, runs every query via `pd.read_sql`, KPI scorecard and metric dictionary, RFM, cohort retention, experiment, business impact (all outputs saved) |
| `reports/growth_memo.md` | One-page memo: Result, Impact, Recommendation, Caveats |
| `requirements.txt` | pandas, numpy, scipy (the notebook also needs jupyter to run) |
| `.gitignore` | Excludes `*.db` and generated CSVs |

## How to run
```bash
pip install -r requirements.txt jupyter
python generate_data.py          # creates users.csv, transactions.csv, experiment.csv
jupyter notebook pesapap_analysis.ipynb   # Kernel > Restart & Run All
```
The notebook builds `pesapap.db` itself and also calls the generator if the CSVs are missing.

## Key findings
- **Data quality:** 31% of transactions (KES 5.0M) pre-date the user's signup. Kept in headline totals, excluded from RFM and cohorts.
- **KPIs (whole period):** KES 15.98M value, 12,000 transactions, 2,943 active users, average transaction KES 1,332, 4.1 transactions per active user. Full-month value growth: +6.9%, +2.0%, +3.1% (Mar to May). January and June are partial months.
- **Products:** Send Money leads (KES 5.6M); Send Money, Bill Pay and Merchant Pay average above KES 1,300 per transaction.
- **RFM:** Champions 544, Loyal 582, At Risk 503, Hibernating 583, Promising 313, Needs Attention 191. Target At Risk first.
- **Cohorts:** about 54% to 59% of a cohort is active in each complete month after signup; incomplete cells are starred.
- **Experiment:** sample-ratio p = 0.037 (slight size imbalance, flagged); covariates balanced.

## Assumptions and limitations
Take rate (1.5%), monthly sign-ups (about 760) and value per converted user (about KES 4,000) are stated assumptions in the notebook and can be changed. "Converted" is not defined in the data and is treated as an activated user.
